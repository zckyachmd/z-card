# Performance validation

Test `pnpm build && pnpm start`, never the development server. Create `tests/performance/results` first. Run `k6 run tests/performance/http.js`; defaults to a safe loopback smoke profile. `PROFILE=baseline RATE=10 DURATION=30s k6 run tests/performance/http.js` provides a repeatable warm-cache baseline. `PROFILE=load` ramps up, sustains traffic, then ramps down. `stress`, `spike`, and `soak` are manual profiles. Configure `BASE_URL`, `RATE`, `VUS`, `DURATION`, `P95`, `P99`, and `OUTPUT` as needed.

Remote targets require `ALLOW_REMOTE=true`; this is a technical guard, not authorization to stress public production. Only load isolated environments you control. `ARTICLE_PATH=/blog/your-published-slug` includes a real article; no article exists initially and the unpublished template must not become public benchmark content. Health has a separate scenario. No scenario sends contact messages or invokes external verification.

Capture commit/runtime/tool versions using `COMMIT_SHA`, `NODE_VERSION`, `NEXT_VERSION`, `K6_VERSION`, `TEST_ENVIRONMENT`, `RESOURCE_LIMITS`. JSON and Markdown summaries contain actual observations; `--out json=tests/performance/results/raw.json` additionally records tagged status samples. Overall RPS includes health and setup; use scenario-tagged data for user traffic. Arrival rate is iterations/s, one request per iteration. Dropped iterations invalidate designated capacity runs. Per-route p95/p99 gates prevent aggregate latency masking.

Run `node tests/performance/resources.mjs PID` alongside the load generator for process CPU/RSS samples. For Docker, use `node tests/performance/resources.mjs z-card tests/performance/results/container.jsonl container`; it captures Docker stats, restart count and configured limits. Stop the sampler after the run. Compare steady-state windows; an upward RSS trend is a diagnostic signal, not proof of a leak. No unexpected restart is acceptable. Investigate CPU, SSR latency, cache state, and payloads before optimizing.

Docker k6: `docker run --rm --network host -v "$PWD:/work" -w /work grafana/k6:2.3.0 run tests/performance/http.js`. On Docker Desktop, use `BASE_URL=http://host.docker.internal:3000` via `-e`. Pin the image version when updating the suite. Browser: `k6 run tests/performance/browser.js` with Chromium installed, or use the matching `grafana/k6:2.3.0-with-browser` image. Browser vitals are synthetic observations, not field p75 Core Web Vitals.

Initial engineering targets: failures <1%, checks ≥99%, each route p95 <500ms and p99 <1000ms, zero dropped page iterations. Threshold failure exits non-zero. Heavy tests are unverified until actually executed; smoke cannot establish capacity. Compare only identical workloads and resource envelopes after warm-up. Preserve raw reports and describe cold/warm cache state.
